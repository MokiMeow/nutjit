# 09 — Testing and debugging

A wrong machine-code byte may crash or return a plausible wrong value, so
nutjit tests behavior and encoding independently.

## Test contract

`make test` runs:

1. `tests/run-tests.sh`: 63 language cases. Valid programs must return the
   expected value in both the JIT and interpreter. Invalid programs must be
   rejected by both.
2. `tests/check-encodings.sh`: exact or structural byte checks for constant
   folding, scratch-register arithmetic, compact immediates, and call-alignment
   padding.

Coverage includes arithmetic wraparound, control flow, declarations, calls,
arity, recursion, invalid literals, and persistent REPL state.

## Disassemble generated code

```bash
./build/nutjit --dump "1 + 2;" 2>&1 |
  grep -E '^[0-9a-f ]+$' | xxd -r -p > /tmp/nutjit-code.bin
objdump -D -b binary -m i386:x86-64 /tmp/nutjit-code.bin
```

Use GDB's `x/i`, `stepi`, and register inspection when a behavioral failure is
not obvious. Generated bytes have no source symbols.

## Common failures

| Symptom | Likely cause |
|---------|--------------|
| SIGILL | malformed instruction bytes |
| SIGFPE | missing `cqo`, division by zero, or signed division overflow |
| Wrong subtraction/comparison | reversed operands |
| Failure only around calls | temporary stack not included in alignment |
| JIT accepts invalid source | missing semantic validation |
| Interpreter/JIT disagree at limits | accidental C++ signed overflow |

For frontend memory bugs, a sanitizer build is useful:

```bash
make clean
make CXXFLAGS="-std=c++17 -Wall -Wextra -Werror -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -Iinclude" test
```

CI performs a clean `-Werror` build, all tests, a sample run, and a benchmark
smoke test on an x86-64 Linux runner.
